# backend-work — 계약대로 동작하고 명세대로 검증한다

입력은 구조 문서(통신·에러 형식·횡단 규약), 계약(무엇을 주고받는가), 데이터 모델(무엇이 어디에), 명세(어떤 규칙으로 동작하는가), 코드 규칙(어떻게 만드는가). 산출물은 그것들대로 동작하는 코드와 그 테스트. **정하지 않는 것은 위 다섯이다.** 브리프의 입력 문서 중 이 task에 필요한 것이 없으면 만들지 않고 계획 단계에서 "막힌 것: 입력 없음"으로 보고한다.

계약이 있으면 계약이 응답의 정본이고, 명세가 검증·권한·상태의 정본이고, 구조 문서가 에러 형식·설정·로깅의 정본이다.

## 시작 전에

0. **입력 문서를 전부 연다.** 하나라도 없고 이 task가 그것을 필요로 하면 여기서 멈춘다.
1. **저장소의 방식을 본다.** 라우팅·핸들러 구조, 검증 방식, 에러 처리 관례, 데이터 접근 계층, 테스트 도구와 픽스처 방식. 기존 엔드포인트 하나를 요청부터 응답까지 따라 읽는다.
2. **계약에서 이 task의 엔드포인트만 뽑는다.** 각각의 요청·응답·에러를 표로. 계약에 없는 필드는 만들지 않는다.
3. **명세에서 규칙을 뽑는다.** 검증 규칙, 상태 전이, 권한, 부수 효과(무엇이 저장·삭제·전송되는가). 명세가 안 정한 규칙은 "명세에 없어 내가 정한 것"에.

## 만들 때

- **경계에서 검증한다.** 입력 검증은 진입점에서 한 번. 검증 실패는 계약의 에러 형식으로. 내부에서 다시 검증하지 않는다.
- **상태 전이는 명시적으로.** 명세에 상태 표가 있으면 코드에도 허용 전이가 한 곳에 있어야 한다. 흩어진 if문으로 만들지 않는다.
- **부수 효과는 명세에 있는 것만.** 명세에 없는 알림, 로그 적재, 캐시, 외부 호출을 넣지 않는다.
- **되돌리기 어려운 것은 하지 않는다.** 마이그레이션 실행, 데이터 삭제, 외부 서비스 호출, 의존성 추가는 브리프에 있을 때만. 없으면 "막힌 것".
- **테스트는 같이 쓴다.** 계약의 예시 값이 픽스처다. 정상 경로, 각 검증 실패, 각 에러 코드, 권한 없음.
- **소유 경로 밖의 공용 모듈을 고치지 않는다.** 필요하면 보고.

## 검증

| 확인 | 방법 |
|---|---|
| 계약 준수 | 실제 요청으로 응답을 받아 계약 예시와 필드 단위 대조 |
| 명세 준수 | 검증 규칙·전이·권한마다 테스트 하나 |
| 기존 영향 | 전체 테스트·빌드·타입체크 |
| 데이터 변경 | 실행 후 저장소 상태를 직접 조회 |

"핸들러를 구현했다"는 완료가 아니다. 계약의 각 엔드포인트가 예시대로 응답하는 출력이 완료다.

## 최적화 task일 때

- **먼저 잰다.** 측정 방법과 전·후 수치를 보고에.
- **동작을 바꾸지 않는다.** 기존 테스트가 그대로 통과해야 한다. 테스트가 없으면 최적화 전에 현재 동작을 고정하는 테스트를 먼저 쓴다.
- **한 가지씩.** 최적화 하나에 측정 하나.

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 화면에서 필드가 undefined | 계약과 다른 필드명. 응답을 계약 예시와 대조하지 않음 |
| 검증이 어떤 경로에서만 됨 | 진입점이 아닌 내부에서 검증 |
| 테스트는 통과인데 실제 요청은 500 | 테스트가 핸들러 함수만 부르고 라우팅·미들웨어를 안 거침 |
| "요청 밖 변경" 지적 | 명세에 없는 로그·캐시·알림 추가 |
| 최적화 후 결과가 달라짐 | 동작 고정 테스트 없이 고침 |
