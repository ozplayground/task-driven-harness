# direction-review — 구현 투입 전에 기준을 의심한다

구현 투입 전 한 번 — 완료 기준이 요구를 담는지, 전제에 근거가 있는지, 안 본 대안이 없는지, 조사가 충분한지.

## 비판하는 쪽이 보는 것

| 종류 | 질문 | 예 |
|---|---|---|
| 전제 | 이 계획이 참이라고 가정한 것에 근거가 있나 | "사용자는 오프라인이 아니다" — 요구 어디에? |
| 대안 | 검토하지 않은 접근이 있나, 검토했다면 왜 버렸나 | 결정 기록의 대안이 하나 |
| 조사 결손 | 결정에 필요한 조사가 빠졌거나 근거가 의견뿐인가. 조사의 축이 요구에서 왔나 | 큐 선택의 근거가 블로그 |
| 완료 기준 | 이 기준을 전부 통과해도 요구가 안 될 수 있나 | "테스트 통과"만 있고 FR-05 동작 기준 없음 |
| 선행 누락 | 결정 없이 만들 수 없는 task가 있나 | 계약 없이 화면·API 동시 투입 |
| 경계 | task 분할이 구조의 경계·데이터 소유권과 맞나 | 한 task가 두 모듈의 데이터를 씀 |
| 범위 | 요구에 없는 것이 들어왔나, 요구가 빠졌나 | wanted 3개인데 task는 2개만 덮음 |

보지 않는 것: 취향, 다른 스택이었으면 하는 바람, 이미 사용자가 결정한 것(`decided_by: user`)의 재론.

## 비판 파일의 절

```markdown
# 비판 round <n>

본 것: <문서 경로 목록>

## 항목
| id | 종류 | 심각도 | 대상 | 내용 | 근거·확인 방법 |
|---|---|---|---|---|---|
| P-C1 | 완료 기준 | blocker | T3 | FR-05(코치 권한)가 어느 task 기준에도 없음 | spec#FR-05 ↔ task 표 |
| P-C2 | 조사 결손 | major | ADR-003 | 시계열 처리량 근거가 의견 등급뿐 | 조사 결과의 근거 표 |
| P-C3 | 대안 | minor | ADR-002 | 모듈러 모놀리스 대안 미검토 | 결정 기록 대안 표 |

## 이 계획대로 가면
두세 문장. 무엇이 만들어지고 무엇이 안 될 것인가.

## 이전 라운드 항목 (round 2 이상)
| id | 상태 | 확인 |
```

| 심각도 | 기준 |
|---|---|
| blocker | 이대로 가면 요구를 만족하지 못하거나, 되돌리기 어려운 결정이 근거 없이 내려진다 |
| major | 실행 중 재작업이나 재계획을 일으킬 가능성이 높다 |
| minor | 알아 두면 좋음. 반영 여부는 처리하는 쪽 재량 |

항목마다 **확인 방법**이 있어야 한다.

## 처리하는 쪽의 절차

내용을 판단하지 않는다. 항목을 **갈라서 보낸다.**

1. 비판 파일을 읽는다. 원문.
2. 항목마다 셋 중 하나를 기록에 적는다.
   - **형식·덮음 문제** (FR이 어느 task에도 없음, 입력 문서 누락, 범위 불일치) → 직접 task 표를 고친다
   - **내용 문제** (대안, 조사 근거, 경계) → 계획을 세운 쪽에 ID를 넘겨 반박 또는 수정을 받는다. 자기 의견으로 닫지 않는다
   - **사용자 결정이 필요한 것** → 사용자에게
3. blocker가 있었으면 round 2. round 2는 이전 ID의 해소 여부만 보고, 새 항목은 blocker만.
4. 왕복 2회. 그래도 blocker면 사용자에게 열린 항목과 함께 올린다.
5. 승인 요청에 "비판 요약: P-C1 반영, P-C2 반영(조사 추가), P-C3 기각(이유)"을 붙인다.

## 비판하는 쪽이 하지 않는 것

- 계획·문서를 고쳐 쓰기. 비판만 한다
- 새 요구 만들기. "이것도 있어야"는 요구가 아니라 제안이고 minor다
- 사용자가 결정한 것 다시 열기
- round 2에 새 major·minor 올리기

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 비판이 전부 "고려해 보세요" | 심각도·확인 방법 없음. 반박 불가능한 비판은 비판이 아님 |
| 비판을 요약해 전달 | 원문·ID로 넘길 것. 요약은 왜곡 |
| 내용 항목을 자기 의견으로 기각 | 내용은 계획을 세운 쪽의 반박으로. 처리하는 쪽은 갈라서 보낼 뿐 |
| round마다 새 항목 | round 2 규칙 위반 |
| 스택을 다시 논함 | 사용자 결정 재론 금지 |
| 구현 투입 뒤에 비판 | 순서 위반. 투입 전이다 |
