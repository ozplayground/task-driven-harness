# unattended — 사용자 없이 도는 run

사용자가 답해야 넘어가는 지점(결정 결손, 승인, 결정 확정, 미검증, 범위 확장)마다 **대체 규칙**을 둔다.

1. **리더가 대신 결정하지 않는다.** 대체는 미리 받은 결정(위임장), 추천+독립 검증의 조합, 아니면 질문 큐다.
2. **되돌릴 수 있는 쪽으로.** 물어볼 사람이 없으니 갈림길에서는 되돌릴 수 있는 대안을 고르고 재검토 조건을 남긴다.
3. **질문은 큐에, run은 계속.** 막힌 결정에 의존하지 않는 task는 돌린다. 의존하는 것만 `blocked`.

## 토글

상태는 파일에 있다. 대화 기억에 두지 않는다.

```
호출됨 ("/unattended", "무인 모드", "무인모드")
  상태 파일 없음 또는 off → 켠다
  상태 파일 on            → 끈다
인수 on / 켜기 말("무인으로 돌려", "알아서 진행해") → 켠다 (이미 켜져 있으면 그대로, 위임장만 갱신)
인수 off / 끄기 말("돌아왔어", "무인 해제")      → 끈다 (이미 꺼져 있으면 그대로)
```

인수로 위임장 항목을 줄 수 있다 (`/unattended 범위: 백엔드만, 미검증: 진행`). 켤 때만 의미가 있다.

**켤 때**

1. 위임장을 읽는다. 없으면 **아래 골격으로 사용자와 함께 채운다.** 채우기 전에 켜지 않는다.
2. 상태 파일에 `on`, 시각, 위임장 버전을 쓴다. notes에도 한 줄.
3. 이후 원장 log의 `--because`에는 적용한 위임장 조항(`mandate §n`)을 함께 적는다.
4. 진행 중인 run이 있으면 그 run의 열린 질문부터 위임장으로 닫아 본다.
5. 사용자에게 한 줄로 답한다: "무인 모드 켬. 위임장 v<n>. 끄려면 다시 부르거나 '돌아왔어'."

**끌 때**

1. 상태 파일에 `off`와 시각. notes에 한 줄.
2. 질문 큐를 순서대로 올린다. 답을 받아 막힌 task를 `ready`로.
3. 자동 결정 목록을 보인다. 사용자가 뒤집는 것은 `superseded` + 의존 task 재작업.
4. 한 줄로 답한다: "무인 모드 끔. 질문 <n>건, 자동 결정 <m>건 — 위부터."

**매 판단 전에** 리더는 상태 파일을 읽는다. 켜져 있으면 대체 규칙, 꺼져 있으면 유인 절차 그대로. 기억으로 판단하지 않는다.

## 위임장 골격

```markdown
---
kind: mandate
version: 1
updated: ...
---
# 위임장

## 범위 상한
무엇까지 만들어도 되나. 이 밖은 질문 큐 (예: "주문 도메인 안. 결제 연동은 안 됨")

## 기본값
결정 결손이 나올 때 쓸 답 (예: 스택은 저장소 기존 것, 없으면 X / 저장소는 Postgres / 인증은 기존 방식)

## 허용된 되돌리기 어려운 결정
아키텍트 추천 + critic 무이의로 자동 확정해도 되는 결정의 종류 (예: 모듈 경계, 데이터 모델). 여기 없는 종류는 질문 큐

## 미검증 처리
"표시하고 진행" 또는 "멈춤"

## 상한
호출 수 / 시간 / 재작업 총량. 넘으면 정리하고 멈춤

## 항상 하지 않는 것
배포, 푸시, 머지, 삭제, 외부 전송. 여기는 고칠 수 없다

## 종료 조건
무엇이 되면 끝인가. 끝나면 무엇을 남기나
```

사용자가 "다 알아서"라고 하면 그것도 위임장이다 — 범위 상한만 요구 문장으로 두고, 되돌리기 어려운 결정은 전부 질문 큐로 가며 되돌릴 수 있는 쪽으로 진행한다.

## 대체 규칙

"사용자에게" 올리게 돼 있는 지점마다.

| 지점 | 유인 | 무인 |
|---|---|---|
| 결정 결손 (intake) | 묻는다 | 위임장 기본값 → 없으면 되돌릴 수 있는 쪽으로 가정 + 질문 큐 |
| 아키텍트의 NFR 질문 | 묻는다 | 기본값 → 없으면 보수적 가정(작은 규모, 단순 구조) + 질문 큐. 아키텍트에게 가정을 명시해 넘긴다 |
| task 표 승인 | 사용자 | critic blocker 0 + 모든 결정이 위임장 안 → 자동 승인, notes에 기록. 하나라도 밖 → 그 항목만 큐, 의존 안 하는 task는 승인 |
| 되돌리기 어려운 결정 확정 | 사용자가 고름 | 허용된 종류면 아키텍트 추천 + critic 무이의 → `decided_by: auto (mandate §n)`. 아니면 `deferred` 가능한지 먼저 보고, 안 되면 큐 |
| 비판 항목 중 "사용자에게" | 사용자 | 큐. 그 항목이 blocker면 의존 task만 막고 나머지 진행 |
| 입력 없음으로 task 추가 | 한 줄 확인 | 범위 상한 안이면 추가 + 기록. 밖이면 큐 |
| 범위 확장 | 승인 | 같음 |
| 재작업 2회 초과 | 사용자 | `blocked` + 큐. 재투입하지 않는다 |
| 미검증 (`inconclusive`) | 사용자 | 위임장의 처리 규칙. 없으면 표시하고 진행 + 큐 |
| 요구 오독 (비판에서 요구 해석 blocker) | 사용자 | **멈춘다** |
| 배포·푸시·머지 | 사용자 | **항상 멈춘다.** 준비까지 하고 끝낸다 |
| 상한 도달 | — | 진행 중 task는 끝내고 새로 던지지 않는다. 종료 보고 |

자동 결정에는 항상 두 인스턴스가 관여한다 — 추천한 쪽과 검증한 쪽. 리더 혼자 닫는 결정은 무인에서도 없다.

## 질문 큐

run 보고서의 §질문. 항목마다:

```markdown
| id | 질문 | 취한 가정 | 가정이 틀리면 무효가 되는 것 | 막힌 task |
|---|---|---|---|---|
| Q1 | 활동 샘플 저장소 — Postgres 파티션 vs Timescale? | 진행 안 함 (되돌리기 어려움, 위임장 밖) | — | D2, I1, I2 |
| Q2 | 페이지 크기 기본값? | 20 | 없음 (되돌릴 수 있음) | — |
```

취한 가정이 있으면 그 가정으로 만든 것에 `[가정 Q2]`를 남긴다.

## 종료 보고

켜진 채 run이 끝나면 종료 보고는 결과보다 **질문 큐와 자동 결정 목록이 먼저**다. run 보고서에 §자동 결정 (결정, 근거 조항, 추천한 쪽, 검증한 쪽) 절을 둔다. run이 끝나도 모드는 저절로 꺼지지 않는다 — 사용자가 끈다.

사용자의 메시지가 오면 리더는 먼저 "돌아온 것인가"를 본다. 끄기 말이면 끈다. 그냥 다음 요구면 켜진 채 진행하되 "무인 모드가 켜져 있다"를 한 줄 알린다.

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 아침에 보니 첫 결손에서 멈춰 있음 | 위임장 없이 켬 |
| 압축 뒤 리더가 사용자에게 묻고 멈춤 | 상태를 기억에 둠. 파일을 읽을 것 |
| 켠 줄 알았는데 꺼짐 | 토글을 두 번 부름. 확실히 하려면 `on`/`off`를 붙일 것 |
| 리더가 스택을 정해 버림 | 대체 규칙 위반. 추천+검증 없는 단독 결정 |
| 질문 큐가 비어 있는데 가정이 잔뜩 | 큐에 안 적고 notes에만 적음. 사용자가 못 찾는다 |
| 무인으로 푸시됨 | "항상 하지 않는 것" 위반. 위임장으로도 열 수 없는 항목 |
| 되돌리기 어려운 결정을 "deferred"로 넘김 | 미루기 기준 오용. 바꾸면 다시 만들어야 하면 큐다 |
