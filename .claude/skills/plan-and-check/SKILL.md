# plan-and-check — 계획을 먼저 쓰고, 계획에 대고 검사한다

계획은 브리프를 받은 쪽이 자기 task 안에서 한다.

## 어디에 쓰나

**자기 보고서 안에.** 별도 파일이 아니다. 보고서의 첫 버전이 계획이고, 마지막 버전이 완료 보고다.

## 1. 시작 전 — 계획

브리프를 읽고 **아무것도 만들기 전에** 쓴다.

보고서 템플릿의 `## 계획` 절에 쓴다. 표 아래에는 모르는 것(어떻게 가정했고 되돌릴 수 있는지)과 막힐 수 있는 것을 적는다.

계획을 쓴 뒤 **한 번 자기 계획을 친다**: 완료 기준(EO) 전부가 어느 행에든 걸리는가. 안 걸리는 EO가 있으면 행을 추가한다. **입력 문서에 없어 만들 수 없는 EO가 보이면 여기서 멈추고 "막힌 것"으로 보고한다.** 계약·설계가 입력인 task에서 그것이 없으면 "내가 정한 것"이 아니라 "막힌 것"이다.

역할별 계획의 모양:
- **만드는 쪽** — 위 표. 행은 산출물 단위(파일·엔드포인트·화면·문서 절), 파일 단위로 잘게 쪼개지 않는다.
- **검증하는 쪽** — 검사 계획. 완료 기준마다 "실행할 것 / 대조할 문서와 항목". 실행할 수 없는 기준은 여기서 `inconclusive` 후보로 표시.
- **구조를 정하는 쪽** — 결정 사슬 중 이번 라운드에 정할 것, 조사가 필요한 것.
- **비판하는 쪽** — 볼 문서 목록과 각 문서에서 칠 전제.

## 2. 진행 중 — 갱신

행 하나를 끝낼 때마다 상태를 바꾸고 파일을 덮어쓴다. 계획이 틀렸으면 **행을 고치고 고쳤다고 적는다** ("3을 둘로 나눔: 검증 규칙이 계약에 두 절").

## 3. 보고 전 — 자기 검증

보고서를 마무리하기 전에 세 대조를 한다. 표로 남긴다.

보고서 템플릿의 `## 자기 검증` 절에 쓴다. 계획, 완료 기준, 범위와 각각 대조하고, 다시 읽어 보며 고친 것을 적는다.

"다시 봤더니"에는 자기 산출물을 **브리프의 독자 입장에서** 한 번 다시 읽고 나온 것을 적는다. 검증하는 쪽이 무엇을 잡을지 예상해 보고, 잡힐 것을 먼저 고친다.

그 다음 `## 계획` 절을 지우거나 `## 진행 상태`로 접고 완료 보고 형식으로 마무리한다. **"다음에 필요한 것"** 절을 잊지 않는다.

## 자기 검증이 아닌 것

- 독립 판정의 대체가 아니다. 판정은 여전히 만들지 않은 쪽이 한다.
- 완료 기준을 낮추는 자리가 아니다.
- 계획 표와 자기 검증 표, 둘이면 된다.

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 계획이 완료 기준을 그대로 옮긴 것 | 할 일이 아니라 결과를 적음. 행은 "무엇을 만든다"여야 |
| 자기 검증이 전부 "확인" | "다시 봤더니"를 안 함. 검증하는 쪽이 잡을 것을 예상 안 함 |
| 계획과 다르게 만들고 계획은 그대로 | 갱신 규칙 위반. 자기 검증이 거짓 |
| 막힌 것을 다 만들고 나서 발견 | 계획 뒤 자기 계획 치기 생략 |
| 계약 없는 필드를 만들고 "내가 정한 것"에 적음 | 그건 막힌 것. 입력이 없으면 만들지 않는다 |
