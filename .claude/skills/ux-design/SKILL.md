# ux-design

입력은 PRD(사용자, 요구사항, 범위)와 아키텍처(실행 단위, 웹 스택). 산출물은 UX 설계 문서와 디자인 시스템 문서. 정하지 않는 것은 각 화면의 구성 요소와 동작(FSD가 정한다), 화면 구현.

## 순서

UX 설계가 먼저, 디자인 시스템이 그 다음이다. FSD는 UX 설계의 화면 목록을 받아 쓰고, 프론트엔드 구현은 디자인 시스템의 컴포넌트를 받아 쓴다.

```
PRD → UX 설계 → FSD → 디자인 시스템 → 프론트엔드 구현
```

## UX 설계 — 사용자에서 화면으로

1. **역할마다 자주 하는 일을 적는다.** PRD의 역할과 요구사항에서 뽑는다. 얼마나 자주, 어떤 상황에서(급한지, 반복인지, 처음인지) 하는지까지. 이것이 기본 진입 화면과 화면 우선순위를 정한다.
2. **정보 구조를 그린다.** 제품이 다루는 대상과 그 관계를 사용자가 보는 방식으로 정리한다. 무엇이 최상위이고 무엇이 그 아래인지. 데이터 모델의 엔티티 관계와 같을 필요는 없다. 사용자가 찾는 순서를 따른다.
3. **내비게이션을 정한다.** 메뉴 항목, 역할별로 보이는 것, 로그인 뒤 기본 화면. 메뉴는 정보 구조의 최상위와 같아야 한다.
4. **화면 목록을 만든다.** 화면마다 번호(SCR-nn), 이름, 어느 요구사항이 쓰는지, 어디서 들어오는지. 요구사항마다 받는 화면이 있어야 한다. 이 번호를 FSD가 그대로 쓴다.
5. **작업별 화면 흐름을 쓴다.** 역할이 자주 하는 일마다 어떤 화면을 어떤 순서로 지나는지, 갈라지는 경우와 돌아가는 경로.
6. **화면 종류별 레이아웃 골격을 정한다.** 목록, 상세, 입력 폼, 대화상자 각각에서 제목·필터·주 동작·본문·부 동작이 놓이는 자리. 개별 화면은 이 골격 안에서 FSD가 채운다.
7. **상호작용 규칙을 정한다.** 저장 시점, 되돌리기, 확인이 필요한 동작, 입력 중 이탈, 목록 갱신 방식, 오류를 보여 주는 자리. 화면마다 다르게 만들어지면 안 되는 것들이다.
8. **상태 표현을 정한다.** 로딩, 빈 목록, 오류, 권한 없음, 성공 알림.
9. **접근성과 입력 환경을 정한다.** 키보드 조작, 대비, 지원하는 화면 폭, 브라우저.

정하기 어려운 것이 있으면 비슷한 제품이 어떻게 하는지 조사한다(`investigator`, 조사 task). 취향으로 정하지 않고 사용자의 작업에서 이유를 찾아 적는다.

## 디자인 시스템 — 규칙과 부품

1. **방향을 한 문단으로 정한다.** UX 설계 1절의 사용자와 상황에서 나와야 한다. 하루 종일 켜 두는 운영 화면과 가끔 쓰는 설정 화면은 밀도와 강조가 다르다.
2. **색을 토큰으로 정한다.** 배경, 표면, 본문, 보조, 주 동작, 상태(성공·경고·위험). 상태 색은 UX 설계의 상태 표현과 맞춘다. 본문과 배경의 대비 기준을 적는다.
3. **타이포 단계를 정한다.** 제목, 소제목, 본문, 보조. 크기, 줄 간격, 굵기, 용도. 글꼴과 대체 글꼴.
4. **간격 단위와 그리드를 정한다.** 기본 단위, 화면 여백, 절 사이, 폼 항목 사이, 최대 폭.
5. **공통 컴포넌트를 정한다.** 버튼, 입력, 표, 상태 배지, 대화상자, 알림 등. 컴포넌트마다 변형, 상태(기본·호버·눌림·비활성·오류·로딩), 크기, 쓰는 자리. UX 설계의 레이아웃 골격과 상호작용 규칙이 요구하는 것이 빠지면 안 된다. 여기 없는 컴포넌트는 프론트엔드 task가 만들지 못하므로, 필요한 것은 다 적는다.
6. **반응형 기준을 정한다.** UX 설계의 화면 폭 범위에 따라 무엇이 달라지는지.
7. **문구 톤을 정한다.** 어조, 버튼 문구 형식, 오류 문구 형식. FSD의 문구 원문이 이것을 따른다.
8. **구현 위치를 적는다.** 토큰 파일과 컴포넌트 디렉터리. 아키텍처의 웹 스택 안에서 정한다.

시각적 선택(팔레트, 타이포, 레이아웃)에서 뻔한 기본값을 피하고 이 제품에 맞는 선택을 하려면 `frontend-design` 스킬을 함께 쓴다.

## 완료 기준

- UX 설계: PRD의 모든 요구사항이 화면 목록의 어느 화면에 걸린다. 역할별로 자주 하는 일마다 화면 흐름이 있다. 상호작용 규칙과 상태 표현이 제품 전체에 하나로 정해져 있다.
- 디자인 시스템: UX 설계의 레이아웃 골격·상태 표현·상호작용 규칙이 요구하는 컴포넌트가 전부 있다. 토큰과 컴포넌트마다 값과 상태가 적혀 있다. 대비 기준과 반응형 범위가 있다.
- 두 문서 모두 정한 것마다 이유가 사용자의 작업이나 조사에서 왔다.
