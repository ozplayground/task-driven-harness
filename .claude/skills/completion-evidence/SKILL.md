# completion-evidence — 완료는 증거와 함께 적는다

"통과합니다"라고 쓰려면 그 명령을 **이 작업 중에** 돌린 출력이 있어야 한다. 코드를 읽어 보니 맞을 것 같다는 판단은 완료가 아니다.

## 증거 수준

완료 기준 하나하나에 아래 넷 중 하나를 붙인다.

| 수준 | 뜻 | 예 |
|---|---|---|
| **실행 검증** | 이 작업 중에 실행했고 출력이 있다 | `npm test` 통과 출력, curl 응답, 브라우저 렌더 확인 |
| **산출물 대조** | 실행은 못 했지만 산출물을 입력 문서와 항목별로 대조했다 | 명세의 화면 4개 ↔ 구현된 라우트 4개 |
| **코드 확인** | 코드를 읽고 논리를 따라갔을 뿐이다 | "이 분기에서 에러를 반환한다" |
| **미검증** | 확인하지 못했다. 이유를 적는다 | "Docker 데몬이 없어 컨테이너 기동은 미검증" |

완료 판정에서 **실행 검증**과 **산출물 대조**만 완료로 친다. 코드 확인과 미검증은 정직하게 적되, 그 기준은 미완이다. 정직하게 적은 미검증이 통과가 되지는 않는다. 미검증을 숨기지 않는다.

## 완료 기준별 최소 증거

| 완료 기준의 종류 | 최소 수준 |
|---|---|
| 테스트 통과 | 실행 검증. 실행 명령과 결과 요약(건수) |
| 빌드·타입체크 | 실행 검증. 종료 코드 |
| 엔드포인트 동작 | 실행 검증. 실제 요청과 응답 |
| 화면 렌더·동작 | 실행 검증 (브라우저·스크린샷·DOM). 불가하면 미검증으로 명시 |
| 문서가 항목을 담음 | 산출물 대조. 항목 목록 ↔ 문서 절 |
| 결함 수정됨 | 실행 검증. **원래 증상을 재현하는 테스트가 통과**. "코드를 고쳤음"은 불충분 |
| 명세대로 구현됨 | 산출물 대조. 명세 항목 ↔ 코드 위치 |

## 보고서 형식

절 이름과 순서를 지킨다. "같이 고친 버그"는 관련 있다고 판정해 이번 task에서 함께 고친 것이고, "요청 밖 발견"은 손대지 않은 것이다. 둘을 섞지 않는다.

```markdown
# <id> <제목>

## 완료 기준
| 기준 | 증거 수준 | 증거 |
|---|---|---|
| tests/api/orders.test.ts 통과 | 실행 검증 | `npm test -- orders` 12 passed, 0 failed |
| GET /orders 가 T1 규격 응답 | 실행 검증 | curl 출력: {"items":[...],"total":3} |
| 화면에서 목록 렌더 | 미검증 | 브라우저 없음. 컴포넌트 테스트는 통과 |

## 변경한 파일
- src/api/orders/handler.ts (신규)
- src/api/orders/schema.ts (신규)
- tests/api/orders.test.ts (신규)

## 같이 고친 버그
| 증상 | 관련성 | 원인 | 수정 | 증명 |
|---|---|---|---|---|
| 목록이 빌 때 500 | 내 소유 경로 안 (handler.ts) | 길이 0 분기 없음 | 조기 반환 1줄 | 재현 테스트 통과 (실행 검증) |

## 명세에 없어 내가 정한 것
- 페이지 크기 기본값 20 (명세 미기재, 되돌릴 수 있음)

## 요청 밖 발견 (손대지 않음)
- src/api/users/handler.ts:41 — null 체크 누락으로 보임. 재현 있음
- src/utils/date.ts — 리팩터링 여지. 버그 아님

## 막힌 것 / 못 한 것
- 없음

## 다음에 필요한 것
- 이 산출물을 쓰려면 있어야 하는 것 / 이 task로 열린 것. 없으면 "없음"
```

"막힌 것: 입력 없음"이면 "다음에 필요한 것"에 그 입력을 만드는 데 필요한 것을 적는다.

절이 비어도 절을 지운 대신 "없음"이라고 쓴다.

## 금지 표현

다음 문장은 증거 없이는 쓰지 않는다. 쓸 때는 증거 수준과 함께 쓴다.

- "정상 동작합니다" → "테스트 12건 통과 (실행 검증). 브라우저 렌더는 미검증"
- "구현 완료했습니다" → 완료 기준 표
- "문제없을 것입니다" → 확인한 것과 안 한 것
- "기존 테스트에 영향 없습니다" → 전체 테스트 실행 결과

## 자기 판정 금지

완료 판정은 보고를 쓴 쪽이 아닌 다른 쪽이 산출물을 직접 보고 한다. 만든 쪽이 "확인했으니 done"이라고 상태를 바꾸지 않는다.

## 흔한 실패

| 증상 | 원인 |
|---|---|
| "테스트 통과"인데 다시 돌리니 실패 | 테스트를 돌리지 않고 코드 확인을 실행 검증으로 적음 |
| 결함이 "수정됨"인데 재현됨 | 증상 재현 테스트 없이 코드만 고침 |
| 보고에 변경 파일이 실제보다 적음 | git status를 보지 않고 기억으로 적음 |
| 미검증이 하나도 없음 | 환경 제약이 전혀 없는 경우는 드물다. 숨겼을 가능성 |
