# spec-authoring — 뒤에서 만들 사람이 결정을 내리지 않게 쓴다

입력은 아이디어·요구·조사 결과·구조 문서. 산출물은 무엇을 만드는지의 정의. 정하지 않는 것은 어떻게 만드나(구조·스택·계약).

## 어떤 문서를 쓰는가

사용자가 요구한 것만 쓴다. "PRD 써줘"면 PRD만. "PRD랑 FSD"면 둘. 사용자가 이미 문서 형식을 갖고 있으면 그 형식을 따른다. 없을 때만 문서 표준의 골격을 쓴다.

| 문서 | 답하는 질문 | 단위 |
|---|---|---|
| **PRD (요구사항 정의서)** | 누가, 왜, 무엇을 요구하는가. 무엇은 안 하는가 | 제품 하나에 하나. 요구사항마다 `REQ-nn` |
| **FSD (기능 명세서)** | 요구사항을 이루는 기능이 각각 정확히 어떻게 동작하는가 | REQ 하나에 파일 하나, 안은 기능(`FN-nn`)별. PRD 없이 쓰지 않는다 |
| **설계 문서** | 왜 이렇게 만들어야 했는가 | 결정과 근거, 고려한 대안, 영향 범위, 되돌리는 방법 |
| **용어집** | 이 도메인의 말을 무엇이라 부르나 | 용어, 정의, 동의어(쓰지 않을 말), 코드·필드에서의 이름 |
| **레퍼런스·가이드** | 외부 독자가 이걸 어떻게 쓰나 | 계약에서 도출. 계약과 어긋나면 계약이 정본 |

## 절차 — PRD

1. **입력을 읽는다.** 사용자의 아이디어·문서·기존 코드. 있는 것을 다시 묻지 않는다.
2. **범위 경계를 먼저 적는다.** 포함보다 **제외**가 중요하다.
3. **요구사항을 나눈다.** 요구사항 하나 = 사용자가 하나의 목적으로 쓰는 기능 단위. 요구사항마다 `REQ-nn`, 정의(무엇을·누가·어디까지), 우선순위, 인수 조건(검증 가능한 문장), 쓸 FSD 경로.
4. **사용자 요구 문장마다 어느 REQ가 받는지 추적 표를 만든다.** 어느 REQ에도 안 걸린 요구 문장이 0이어야 한다.
5. **비기능 요구는 측정 가능한 값으로.** "빠르게" 대신 "목록 조회 1초 이내".

## 절차 — FSD

1. **PRD의 REQ 하나를 받는다.** 문서 머리에 REQ 정의와 인수 조건을 그대로 인용한다. 인용이 FSD의 범위다 — 밖으로 넓히지 않고, 안에서 빠뜨리지 않는다.
2. **REQ를 기능으로 나눈다.** 기능 하나 = 사용자가 한 번의 목적으로 끝까지 수행하는 동작 묶음(예: 목록 조회, 생성, 수정, 게시). 기능마다 `FN-nn`, 이름, 한 줄 정의, 받는 인수 조건. 인수 조건마다 받는 FN이 있어야 한다. 아래 3–10을 기능마다 쓴다.
3. **화면부터 나열한다.** 화면마다 `SCR-nn`, 진입 경로, 다른 화면으로의 이동. 화면이 없는 기능(API만, 배치)이면 "해당 없음 — 이유"와 그 대신의 트리거.
4. **화면마다 구성 요소를 전부 적는다.** 요소마다 ID, 종류, 라벨, 기본값, 필수 여부, 입력 제약, 표시 조건, 눌렀을 때의 동작. 목록 화면은 컬럼·정렬·필터·검색·페이지 크기. 상태는 로딩·빈 목록·오류·권한 없음·정상 모두.
5. **흐름을 단계로 쓴다.** 정상, 대안, 예외. 상태가 있으면 전이 표.
6. **규칙은 `BR-nn`로.** 하나에 규칙 하나. "적절히"·"필요 시" 금지.
7. **문구는 원문으로.** 검증 오류, 확인 대화상자, 알림, 빈 상태 안내. 문구가 정해지지 않은 절은 없다.
8. **권한은 동작 × 역할 표.** 볼 수 없는 경우 무엇이 보이는지까지.
9. **처리·데이터·연동을 적는다.** 동작마다 전 조건·후 조건·부수 효과, 읽고 쓰는 엔티티·필드, 호출하는 API(계약이 없으면 필요한 것 목록).
10. **경계를 적는다.** 동시 편집, 한도 초과, 타임아웃, 참조 대상이 사라졌을 때.
11. **추적 절로 닫는다.** REQ 인수 조건마다 어느 FN·절이 받는지. 못 정한 것은 `[미결]`, 임시로 정한 것은 `[가정]`.

## 공통

- **결정을 미루지 않는다.** 정보가 부족하면 임시 결정을 내리고 `[가정]`으로 표시하고 근거를 적는다. 되돌리기 어려운 결정(저장 방식, 인증, 공개 API 형태)은 `[결정 필요]`로 표시하고 완료 보고의 "막힌 것"에 올린다.
- **해당 없음도 적는다.** 빈 절은 잊은 것과 구분되지 않는다. "해당 없음 — 이유".
- **사용자가 준 문서를 보강할 때**는 원문을 고치지 않고 덧붙인다. 바꿔야 하면 바꾼 곳과 이유를 문서 상단에 표로.

## 완성도 점검 — FSD

보고 전에 FSD마다 센다. 0이 아니면 미완성이다.

- 문서 표준 골격 절 중 비어 있고 "해당 없음"도 아닌 절
- 기본값·입력 제약·동작 칸이 빈 구성 요소
- 원문 없이 "오류 메시지 표시"로만 적힌 오류
- 역할 표에 없는 동작
- 어느 FN에도 안 걸린 REQ 인수 조건
- 골격 절이 빠진 FN

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 구현자가 "명세에 없어 내가 정한 것"을 열 개 보고 | FSD의 구성 요소·검증·문구·권한 칸이 비어 있음 |
| "명세와 다르다"를 판정할 수 없음 | REQ·BR·SCR에 ID가 없어 대조할 기준이 없음 |
| FSD가 PRD를 다시 옮겨 적은 수준 | 화면·구성 요소·흐름 절을 쓰지 않음. FSD는 REQ 하나를 화면과 규칙 단위까지 내린다 |
| 제품 전체가 FSD 한 파일 | REQ마다 FSD를 나누지 않음 |
| FSD가 요구사항 문장을 되풀이하고 기능이 안 보임 | REQ를 기능(FN)으로 나누지 않음 |
| 화면 4개인데 명세는 3개 | 범위 절에 제외를 안 적어 구현자가 추가함 |
| 문서가 길기만 하고 결정이 없음 | 결정을 "추후 논의"로 미룸 |
| 사용자가 "이거 내가 준 거랑 다른데" | 원문을 고쳐 씀 |
