# research — 주장마다 출처를, 비교에는 축을 붙인다

입력은 닫힌 질문 또는 비교 대상과 목적. 산출물은 근거가 붙은 답 또는 비교표. 정하지 않는 것은 **무엇을 택할지** — 추천은 "이 기준이면 A"의 형태로만 쓴다.

## 두 형태

| 형태 | 질문 모양 | 산출물 핵심 |
|---|---|---|
| 조사 | "X는 어떻게 / 무엇이 / 왜" | 답 + 근거 표 + 반증 시도 |
| 벤치마크 | "A·B·C 중 / 남들은 어떻게" | 비교표(축 × 대상, 셀마다 근거) + 가져올 것·버릴 것 |

## 절차

1. **질문을 닫는다.** 브리프의 질문을 "답이 무엇이면 끝나는가"로 다시 쓴다. 안 닫히면 하위 질문으로 쪼갠다. 벤치마크면 **축을 요구에서 도출한다** — NFR·제약·브리프의 결정 기준이 축이다. 축이 먼저고 대상은 그 다음.
2. **대상을 정한다.** (벤치마크) 3~5개. 선정 기준을 적는다 — 왜 이것들이고 왜 저것은 뺐나.
3. **출처 등급을 붙인다.**

   | 등급 | 무엇 | 예 |
   |---|---|---|
   | 1차 | 공식 문서, 소스 코드, 직접 측정·실행 | API 레퍼런스, 저장소, 로컬 벤치 |
   | 2차 | 검증 가능한 보고·사례 | 공개 포스트모템, 논문, 표준 |
   | 의견 | 블로그, 답변, 평판 | — |

   주장마다 등급. 1차 없는 주장은 "미확인"이다. 의견만 있는 셀은 비운다.
4. **반증을 찾는다.** 답이 보이면 반대 근거를 한 번 찾는다. "X는 Y를 지원한다" → 지원 안 하는 조건·버전·한도를 찾는다. 찾은 것을 적는다.
5. **멈춘다.** 셋 중 하나면: 하위 질문 전부에 1차 근거가 있다 / 같은 출처가 반복된다 / 두 번 더 찾아도 새 것이 없다.
6. **쓴다.** 아래 절 구성으로. 문서 머리말의 입력 목록에 브리프가 준 요구·NFR 문서를 적는다.

## 산출물의 절

```markdown
## 질문
닫힌 질문 (하위 질문 목록)

## 답 (10줄 이내)
결론. 벤치마크면 "기준 K이면 A, 기준 L이면 B"

## 근거
| 주장 | 출처 | 등급 | 확인 방법 |
|---|---|---|---|

## 비교 (벤치마크)
선정 기준: ...
| 축 (출처: NFR-03) | A | B | C |
|---|---|---|---|
| 처리량 | 1만/s (1차: 문서 §x) | 미확인 | ... |

## 가져올 것 · 버릴 것 (벤치마크)
| 대상의 무엇 | 가져옴/버림 | 이유 (요구 근거) |

## 반증 시도
찾은 반대 근거와 그 영향. 시도했으나 없으면 그렇게

## 확인하지 못한 것
무엇을 어디서 못 찾았나

## 추정 (근거 약함)

## 다음에 필요한 것
이 답으로 결정할 수 있는 것 / 더 조사해야 결정되는 것
```

보고서에는 계획·자기 검증 표와 완료 기준 표를 쓴다. 증거 수준은 "산출물 대조"(출처 열람)다.

## 완료 기준

- 질문이 닫혀 있고 답이 그 질문에 직접 답함
- 주장마다 출처와 등급. 1차 없는 주장은 미확인 표기. 출처는 실제로 열어서 확인할 수 있어야 함
- 벤치마크: 축이 요구에서 왔고(출처 표기), 대상 선정 기준이 있고, 셀마다 근거
- 반증 시도 절이 비어 있지 않음
- 추천이 있으면 조건부("기준이면")

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 출처를 열어 보니 다른 말 | 2차·의견을 1차로 표기 |
| 비교표 축이 제품 마케팅 항목 | 축을 요구가 아니라 대상에서 도출 |
| "A가 최고" | 조건 없는 추천 |
| 보고서 60쪽 | 충분성 기준 미사용 |
| 우리 요구와 무관한 대상 비교 | 선정 기준 없음 |
