# security-compliance

## 요건을 정하는 순서

1. **데이터를 분류한다.** 제품이 다루는 데이터를 전부 적고 분류한다. 개인정보, 민감정보, 결제정보, 인증 정보(비밀번호·토큰·키), 사용자 생성 콘텐츠, 운영 데이터. 데이터마다 어디서 생기고 어디에 저장되고 어디로 나가는지 적는다. 다루지 않는 데이터에 대한 요건은 만들지 않는다.
2. **적용되는 규제와 요건을 찾는다.** 법령(개인정보보호법, 전자상거래법, 정보통신망법 등), 스토어 정책, 심사 기준(ISMS, SOC 2 등), 회사 규정. 적용 이유와 원문 위치를 적는다. 원문은 조사로 확인하고 기억으로 인용하지 않는다. 적용되지 않는 것은 왜 아닌지 한 줄.
3. **위협 모델을 만든다.** 누가(외부 공격자, 인증된 사용자, 다른 테넌트, 내부 운영자, 침해된 의존성), 무엇을(데이터 유출, 권한 상승, 서비스 중단, 변조, 비용 유발), 어느 경로로(입력, 인증, 외부 호출, 저장소, 로그, 의존성, 배포 파이프라인). 제품에 없는 경로는 없다고 적는다.
4. **보안 요건을 번호로 적는다.** `S-nn`. 영역은 아래 표. 요건마다 어느 위협에 대한 것인지, 설계의 어느 문서·절에 강제되는지, 무엇으로 확인하는지 적는다. 확인할 수 없는 요건은 쓰지 않는다.
5. **컴플라이언스 요건을 번호로 적는다.** `C-nn`. 동의·고지, 보관·삭제·이전, 접근 통제, 기록 의무. 보관 기간과 삭제 방식은 데이터 모델을 바꾸므로 데이터 모델보다 먼저 확정한다.
6. **아키텍트에게 넘길 것을 가른다.** 인증 모델, 시크릿 전달 방식, 암호화 위치, 보관·삭제 정책, 외부 호출 허용 목록은 레벨 1이다. 요건으로 적고 결정은 아키텍트가 한다.

## 보안 요건 영역

| 영역 | 정할 것 |
|---|---|
| 인증·권한 | 누가 어떻게 인증되는가, 역할과 권한 표, 권한 검사가 어느 계층에서 일어나는가, 세션·토큰 수명과 폐기 |
| 시크릿 | 무엇이 시크릿인가, 어디에 보관하고 어떻게 전달하는가(환경변수·파일·비밀 관리자), 로그·에러·응답·저장소에 남지 않게 하는 방법, 회전 |
| 전송·저장 암호화 | 어떤 데이터가 전송 중·저장 시 암호화되는가, 키는 어디에 |
| 입력 검증 | 모든 외부 입력의 검증 위치와 규칙, 크기·형식·범위 한도, 인젝션(SQL·명령·경로·템플릿) 차단 |
| 외부 호출 | 서버가 호출할 수 있는 주소의 허용 목록, 사용자 입력이 주소가 되는 경로(SSRF), 타임아웃과 재시도 |
| 로그·감사 | 남기면 안 되는 것(비밀번호, 토큰, 개인정보 원문), 남겨야 하는 것(인증 실패, 권한 거부, 관리자 행위), 보관 기간 |
| 의존성·빌드 | 의존성 고정과 취약점 점검, 빌드 파이프라인의 시크릿 접근, 컨테이너 이미지 출처 |
| 다중 테넌트·격리 | 테넌트 사이 데이터 경계, 검사 위치 |
| 비용·남용 | 요율 제한, 유료 외부 호출의 상한, 무한 루프·과도한 실행 차단 |

## 검토하는 방법

검토 대상이 무엇이든 순서는 같다. 요건 문서가 있으면 요건 번호 대비로, 없으면 위 영역 대비로 본다.

1. 검토 계획을 먼저 쓴다. 대상의 어느 부분을 어느 요건·영역으로 볼지.
2. 대상을 읽는다. 코드는 3-dot diff 범위. 문서는 원문.
3. 항목마다 지켜졌는지, 안 지켜졌는지, 대상에 해당 없는지 셋 중 하나로 적는다.
4. finding에는 위치, 어느 요건·영역에 어긋나는지, 공격 경로 한 줄, 재현 또는 확인 방법을 적는다.

대상별로 특히 볼 것.

| 대상 | 볼 것 |
|---|---|
| 아키텍처 | 인증 모델과 권한 검사 계층, 시크릿 전달 방식, 암호화 위치, 외부 연동의 신뢰 경계, 보관·삭제 정책이 결정됐는지 |
| 계약·API | 인증이 필요한 엔드포인트에 인증이 있는지, 권한별 응답 차이, 에러에 내부 정보가 새는지, 입력 한도, 목록 조회의 테넌트 필터 |
| 데이터 모델 | 민감 필드의 암호화·마스킹, 보관 기간과 삭제 방식, 삭제 시 참조 처리, 감사 로그 |
| 코드 | 시크릿 하드코딩·로그 출력, 입력 검증 누락, 권한 검사 누락, 사용자 입력이 주소·경로·쿼리·명령이 되는 곳, 외부 호출 허용 목록, 토큰 저장 위치, 의존성 추가 |
| CI·배포 | 시크릿이 로그·아티팩트에 남는지, 워크플로 권한, 이미지 출처, 브랜치 보호 |

## 심각도

| 심각도 | 기준 |
|---|---|
| blocker | 데이터 유출, 권한 상승, 시크릿 노출, 인젝션이 지금 가능하다. 또는 규제 요건을 어긴다 |
| major | 조건이 갖춰지면 위와 같아진다. 방어가 한 겹뿐이다. 감사·로그 요건 누락 |
| minor | 강화하면 좋은 것. 재작업 대상이 아니다 |
