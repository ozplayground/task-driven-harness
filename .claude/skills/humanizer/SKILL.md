# humanizer — 사람이 쓴 문서로

문서는 동료에게 설명하듯 쓴다. 읽는 사람이 다음에 무엇을 해야 하는지, 왜 그렇게 정했는지가 바로 보여야 한다. 아래는 쓰기 전과 쓴 뒤에 대조하는 규칙이다.

## 문장

- 한 문장에 생각 하나. 20자에서 60자 사이가 보통이다. 길어지면 끊는다.
- 주어와 동사로 말한다. "~에 대한 처리를 수행한다" 대신 "~를 처리한다".
- 사실은 수치와 이름으로 말한다. "빠르다" 대신 "응답 1초 안", "많은 테스트" 대신 "테스트 194개". 모듈·함수·필드는 실제 이름으로.
- 판단에는 근거를 붙인다. "적절하다"고 쓰지 않고 무엇 때문에 그렇게 정했는지 쓴다.
- 한계는 숨기지 않는다. 안 되는 것, 정하지 않은 것, 조건이 붙는 것은 그대로 쓴다.
- 번역투를 쓰지 않는다. "~에 대한 책임을 가진다" → "~를 맡는다". "~를 가능하게 한다" → "~할 수 있다". "~를 확실히 하기 위해" → "~하도록". "~에 있어" → "~에서". "~적인" 남발 금지.

## 넣지 않는 것

| 종류 | 예 | 대신 |
|---|---|---|
| 과장과 미사여구 | 혁신적인, 강력한, 완벽한, 궤도에 올린, 극대화, 원천 차단, 무결점 | 사실만 |
| 빈 총평 | "본 문서는 프로젝트의 성공에 기여할 것으로 기대된다" | 지운다 |
| 서두 인사 | "본 문서는 ~를 다룬다. 이를 통해 ~" | 첫 문장부터 내용 |
| 영문 병기 | "요구사항 정의서 (Product Requirements Document)", "개요 (Executive Summary)" | 한글만. 고유명사와 코드만 영문 |
| 절 제목의 수식 | "핵심 성공 지표", "5대 원칙", "3단계 전략" | "성공 지표", "원칙", "전략" |
| 번호 남발 | 문단 하나로 될 설명을 1, 2, 3으로 쪼갠 것 | 순서가 있을 때만 번호. 설명은 문단 |
| 볼드 남발 | 문장마다 굵은 글씨 | 표 제목과 정의하는 낱말에만 |
| 이모지, 체크 표시, 화살표 기호 | ✅ ❌ → ⭐ | 글자로 쓴다 |
| 빈 칸 채우기 | 모든 항목에 "해당 없음", "우수", "만족", "N/A" | 해당 없으면 이유를 한 줄. 판단이면 근거 |
| 자기 지칭 | "AI가", "에이전트가", "본 검토자는" | 사람이 쓴 문서에는 쓰는 사람이 드러나지 않는다 |
| 작업 경위 | "이번 라운드에서", "리뷰 반영하여", "재작업 결과" | 결정된 내용만 |
| 확신 표현 | "명확히", "확실히", "완벽히", "100%" | 지운다. 수치가 있으면 수치 |
| 반복 요약 | 절 끝마다 "정리하면", "결론적으로" | 지운다 |

## 구조

- 개념과 배경은 두세 문장의 문단으로 쓴다. 표와 목록은 비교할 것이나 나열할 것이 있을 때만.
- 표의 칸은 한두 문장이다. 표 안에 문단을 넣지 않는다. 길어지면 표를 풀어 문단으로.
- 절 제목은 그 절에 무엇이 있는지 말하는 명사구다. 문장이나 질문으로 쓰지 않는다.
- 같은 내용을 개요에서 말하고 본문에서 또 말하지 않는다.
- 문서 끝에 결론·요약 절을 붙이지 않는다. 템플릿에 있는 절만.

## 문서 종류마다

| 문서 | 사람이 쓴 것과 AI가 쓴 것의 차이 |
|---|---|
| PRD, FSD | 사용자가 겪는 상황을 구체적으로 쓴다. "효율적인 관리" 대신 "담당자가 하루 200건의 주문을 상태별로 걸러 본다" |
| 아키텍처, 결정 기록 | 고르지 않은 대안과 그 이유, 감수한 것을 쓴다. 고른 것을 칭찬하지 않는다 |
| 설계 | 무엇이 어디를 거쳐 어떻게 되는지 순서대로. 형용사 없이 |
| 조사 | 출처와 수치. 확인하지 못한 것을 확인하지 못했다고 |
| 리뷰, 비판 | 위치와 재현. "잘 만들었다"는 말은 finding이 아니다 |
| 테스트 보고 | 돌린 것과 결과. 돌리지 않은 것은 돌리지 않았다고 |
| 운영 문서 | 운영자가 그 순간 할 명령과 확인할 것. 설명은 그 다음 |

## 쓴 뒤에

문서를 처음부터 끝까지 읽는 사람으로서 읽는다. 다음이 하나라도 있으면 고친다.

- 지워도 뜻이 안 변하는 문장
- 수치나 이름으로 바꿀 수 있는 형용사
- 이유 없는 판단
- 괄호 안 영문
- 한 절에 볼드 셋 이상
- 목록 항목이 전부 한 문장인 목록 (문단으로 합친다)
