# UX 설계

| 항목 | 내용 |
|---|---|
| 대상 | 제품 이름 |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 제품 전체의 정보 구조와 화면 흐름, 사용자와 상호작용하는 방식을 정한다. PRD의 요구사항을 화면과 이동으로 풀어내며, FSD는 여기서 정한 화면 목록 안에서 각 화면의 구성 요소를 상세화한다. 시각적 규칙(색, 타이포, 컴포넌트 모양)은 디자인 시스템 문서가 정하고 여기서는 정하지 않는다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 사용자와 목적

역할마다 이 제품을 열어서 가장 자주 하는 일과 그때의 상황(급한지, 반복적인지, 처음인지)을 적는다. 화면 우선순위와 기본 진입 화면이 여기서 정해진다.

작성 예:

| 역할 | 자주 하는 일 | 상황 |
|---|---|---|
| 담당자 | 결제 실패 건 확인과 재시도 | 하루 여러 번, 빨리 처리해야 함 |
| 조회 | 특정 주문 찾기 | 고객 문의를 받은 상태에서 이름·번호로 검색 |
| 관리자 | 사용자 등록 | 가끔 |

## 2. 정보 구조

제품이 다루는 대상(주문, 결제 시도, 사용자 등)과 그 사이 관계를 사용자가 보는 방식으로 정리한다. 무엇이 최상위이고 무엇이 그 아래에 속하는지, 어디서 어디로 가는지를 그린다.

작성 예:

> 최상위는 주문이다. 결제 시도는 주문 상세 안에서만 본다. 사용자 관리는 별도 영역이다.
>
> 주문 목록 → 주문 상세 → 결제 시도 이력
> 결제 실패 목록 → 주문 상세
> 사용자 목록 → 사용자 상세

## 3. 내비게이션

전체 메뉴 구조와 역할별로 보이는 항목, 기본 진입 화면을 적는다.

작성 예:

| 메뉴 | 화면 | 관리자 | 담당자 | 조회 |
|---|---|---|---|---|
| 주문 | 주문 목록 | O | O | O |
| 결제 실패 | 결제 실패 목록 | O | O | O |
| 사용자 | 사용자 목록 | O | X | X |

> 로그인 뒤 기본 화면: 담당자는 결제 실패 목록, 그 밖은 주문 목록.

## 4. 화면 목록

모든 화면에 번호(SCR-nn)와 이름을 붙이고, 어느 요구사항이 쓰는지, 어디서 들어오는지 적는다. FSD는 이 번호를 그대로 쓴다.

작성 예:

| 번호 | 화면 | 요구사항 | 진입 |
|---|---|---|---|
| SCR-01 | 주문 목록 | REQ-01 | 메뉴, 로그인 후 기본 |
| SCR-02 | 주문 상세 | REQ-01, REQ-02 | SCR-01·SCR-03에서 행 선택 |
| SCR-03 | 결제 실패 목록 | REQ-02 | 메뉴 |
| SCR-04 | 사용자 목록 | REQ-03 | 메뉴 (관리자) |

## 5. 화면 흐름

주요 작업마다 어떤 화면을 어떤 순서로 지나는지 적는다. 갈라지는 경우와 되돌아가는 경로도 적는다.

작성 예:

> 결제 실패 처리: SCR-03에서 행 선택 → SCR-02에서 실패 사유 확인 → "재시도" → 확인 대화상자 → SCR-02에 상태 '결제 대기' 표시 → 목록으로 돌아가면 그 주문은 SCR-03에서 빠져 있다.

## 6. 화면 레이아웃 골격

화면 종류(목록, 상세, 입력 폼, 대화상자)마다 공통 배치를 정한다. 어디에 제목, 필터, 주 동작 버튼, 표, 부 동작이 놓이는지. 개별 화면의 구성 요소는 FSD에 적는다.

작성 예:

| 종류 | 배치 |
|---|---|
| 목록 | 상단 제목과 주 동작 버튼(오른쪽), 그 아래 필터 줄, 표, 하단 페이지 이동 |
| 상세 | 상단 제목과 상태 배지, 왼쪽 2/3 본문(항목별 절), 오른쪽 1/3 동작 버튼과 이력 |
| 입력 폼 | 한 열, 필수 항목 먼저, 저장·취소는 하단 고정 |
| 확인 대화상자 | 제목, 한 문장 설명, 취소(왼쪽)·확인(오른쪽) |

## 7. 상호작용 규칙

제품 전체에서 같아야 하는 동작을 적는다. 저장 시점, 되돌리기, 확인이 필요한 동작, 입력 중 이탈, 목록 갱신, 오류 표시 위치.

작성 예:

| 규칙 |
|---|
| 되돌릴 수 없는 동작(재시도 요청, 삭제)은 확인 대화상자를 거친다. 되돌릴 수 있는 동작은 바로 실행하고 알림만 띄운다 |
| 입력을 바꾼 뒤 다른 화면으로 나가면 "저장하지 않은 변경이 있습니다" 확인을 받는다 |
| 서버 오류는 화면 상단 알림 띠에, 입력 오류는 해당 칸 아래에 표시한다 |
| 목록 검색은 입력을 멈춘 뒤 300ms에 자동 조회한다 |

## 8. 상태 표현

로딩, 빈 목록, 오류, 권한 없음, 성공 알림을 화면 전체에서 어떻게 보이는지 정한다.

작성 예:

| 상태 | 표현 |
|---|---|
| 로딩 | 표 자리에 스켈레톤 3줄. 1초 넘으면 "불러오는 중" 문구 |
| 빈 목록 | 가운데 한 문장 안내와, 있으면 첫 동작 버튼 |
| 권한 없음 | 메뉴 자체가 보이지 않는다. URL로 직접 들어오면 "권한이 없습니다" 화면 |
| 성공 | 오른쪽 아래 알림 3초 |

## 9. 접근성과 입력 환경

키보드 조작, 대비, 화면 크기 범위, 브라우저 범위를 적는다.

작성 예:

> 모든 동작은 키보드로 할 수 있어야 한다(Tab 순서는 화면 배치 순서). 표는 1280px 이상 기준으로 설계하고 1024px까지는 가로 스크롤을 허용한다. 모바일은 범위 밖. 브라우저는 최신 Chrome·Edge.

## 10. 대조 표

이 문서가 받아내는 요구사항과, 따르는 결정 기록을 적는다.

작성 예:

| 요구사항 | 화면 |
|---|---|
| REQ-01 주문 조회 | SCR-01, SCR-02 |
| REQ-02 결제 실패 처리 | SCR-03, SCR-02 |
