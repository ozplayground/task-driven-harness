# 모니터링

| 항목 | 내용 |
|---|---|
| 대상 | 제품 이름 |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 무엇을 보고 언제 사람을 부르는지 정한다. 지표마다 어디서 얻는지, 정상 범위가 무엇인지, 어떤 조건이면 알람이 가는지, 알람을 받으면 런북의 어느 절을 보는지 적는다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 지표

보는 지표를 나열한다. 지표마다 어디서 나오는지와 정상 범위.

작성 예:

| 지표 | 어디서 | 정상 범위 |
|---|---|---|
| API 5xx 비율 | api 로그 집계 | 0.1% 미만 |
| 결제 대기 10분 초과 주문 수 | DB 쿼리, 1분마다 | 0건 |
| 큐 대기 작업 수 | procrastinate 테이블 | 100건 미만 |
| DB 디스크 사용률 | VM | 80% 미만 |

## 2. 알람

알람 조건마다 임계값과 지속 시간, 누구에게 가는지, 대응하는 런북 절을 적는다.

작성 예:

| 조건 | 임계값 | 받는 사람 | 런북 |
|---|---|---|---|
| API 5xx 비율 | 1% 이상 5분 지속 | 당번 개발자 | 런북 §1 |
| 결제 대기 10분 초과 | 1건 이상 | 당번 개발자 | 런북 §2 |
| DB 디스크 | 90% 이상 | 당번 개발자 | 런북 §3 |

## 3. 대시보드

대시보드가 어디 있고 무엇을 보여 주는지 적는다.

작성 예:

> Grafana `https://grafana.internal/d/orders`. 위 지표 네 개와 시간대별 주문 생성 수.

## 4. 로그 조회

로그가 어디에 쌓이고 어떻게 찾는지 명령이나 쿼리로 적는다.

작성 예:

> 로그는 VM의 `/var/log/orders/*.log`에 JSON 한 줄씩 쌓인다. 요청 하나를 따라가려면 `grep '"request_id":"<id>"' /var/log/orders/api.log`.
