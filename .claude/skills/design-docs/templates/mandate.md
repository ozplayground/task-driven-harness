# 위임장

| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 사용자가 자리를 비운 동안 리더가 사용자 대신 어디까지 결정해도 되는지 정한다. 여기 없는 결정은 리더가 내리지 않고 질문으로 남긴다. 사용자가 직접 채우거나 리더가 질문해서 받은 답을 그대로 적는다. 리더가 추측으로 채우지 않는다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 범위 상한

무엇까지 만들어도 되는지 적는다. 이 밖의 일은 하지 않고 질문으로 남긴다.

작성 예:

> 주문 조회, 결제 실패 처리, 사용자·권한 관리까지. 환불과 배송 추적은 하지 않는다. 결제 대행사는 A사 하나만 연동한다.

## 2. 기본값

결정해야 할 것이 나왔는데 답이 없을 때 쓸 답을 적는다.

작성 예:

> 스택은 저장소에 이미 있는 것을 따른다. 없으면 Python·FastAPI·PostgreSQL. 수치 한도(페이지 크기, 타임아웃)는 보수적으로 정하고 [가정]으로 표시한다.

## 3. 자동으로 확정해도 되는 결정

아키텍트가 추천하고 critic과 리뷰어가 문제를 찾지 못하면 사용자 확인 없이 확정해도 되는 결정의 종류를 적는다. 여기 없는 종류는 질문으로 남긴다.

작성 예:

> 모듈 경계, 데이터 모델, 작업 큐 방식. 인증 방식과 외부 서비스 연동은 질문으로 남긴다.

## 4. 검증하지 못한 것의 처리

검증할 수 없는 항목이 나오면 표시하고 계속 진행할지, 멈출지 적는다.

작성 예:

> 표시하고 진행한다. run 보고서의 "검증하지 못한 것"에 모아 둔다.

## 5. 상한

호출 수, 시간, 재작업 횟수의 상한을 적는다. 넘으면 정리하고 멈춘다. 상한이 없으면 없다고 쓴다.

작성 예:

> 재작업은 task당 2회. 전체 시간 상한은 없다.

## 6. 절대 하지 않는 것

배포와 외부 전송은 항상 하지 않는다. 그 밖에 더할 것이 있으면 적는다. git 작업(커밋·푸시·PR·머지)은 git-workflow가 정한 대로 리더가 한다.

작성 예:

> 배포, 외부 전송, 유료 API 호출.

## 7. 종료 조건

무엇이 되면 끝인지, 끝나면 무엇을 남기는지 적는다.

작성 예:

> 1절 범위의 구현이 전부 리뷰를 통과하거나, 남은 일이 모두 질문에 막혔을 때. 끝나면 run 보고서를 남기고, 문제가 있는 것 중심으로 쓴다.
