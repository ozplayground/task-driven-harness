# 보안 요건

| 항목 | 내용 |
|---|---|
| 적용 대상 | 제품 이름 |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 이 제품이 어떤 위협에 노출되고, 그래서 설계와 구현이 무엇을 반드시 지켜야 하는지 정한다. 아키텍처 문서와 데이터 모델보다 먼저 있어야 한다. 인증 모델, 시크릿 전달 방식, 암호화 위치, 보관·삭제가 구조를 바꾸기 때문이다. 규제·심사 요건은 compliance 문서에 따로 있고, 이 문서는 그 번호(`C-nn`)를 가리킨다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 대상 데이터와 경계

제품이 다루는 데이터를 분류하고, 어디서 생겨 어디에 저장되고 어디로 나가는지 적는다. 그 다음 신뢰 경계를 적는다. 사용자 브라우저와 서버 사이, 서버와 외부 서비스 사이, 테넌트 사이처럼 신뢰 수준이 바뀌는 곳이다.

작성 예:

| 데이터 | 분류 | 생기는 곳 | 저장 | 나가는 곳 |
|---|---|---|---|---|
| 주문자 이름, 연락처 | 개인정보 | 주문 생성 | PostgreSQL orders | 결제 대행사(이름만) |
| 결제 대행사 API 키 | 시크릿 | 운영자가 등록 | 시크릿 파일 | worker → 결제 대행사 |
| 세션 토큰 | 인증 정보 | 로그인 | 서버 메모리, 브라우저 쿠키 | 없음 |

> 신뢰 경계: 브라우저 ↔ api(HTTP, 모든 입력은 신뢰하지 않음), worker ↔ 결제 대행사(HTTPS, 응답의 금액은 주문과 대조), 테넌트 사이는 없음(단일 테넌트).

## 2. 위협 모델

누가, 무엇을, 어느 경로로 노리는지 적는다. 제품에 없는 경로는 없다고 적는다.

작성 예:

| 번호 | 누가 | 무엇을 | 경로 |
|---|---|---|---|
| T-01 | 외부 공격자 | 다른 사용자의 주문 조회 | 주문 ID 추측, 권한 검사 누락 |
| T-02 | 인증된 담당자 | 관리자 기능 실행 | 역할 검사가 화면에만 있고 API에 없음 |
| T-03 | 외부 공격자 | 서버가 내부 주소를 호출하게 함 | 결제 콜백 URL을 사용자가 입력 |
| T-04 | 침해된 의존성 | 시크릿 유출 | 빌드 파이프라인에서 환경변수 읽기 |

## 3. 보안 요건

요건을 번호(`S-nn`)로 적는다. 요건마다 어느 위협에 대한 것인지, 설계의 어느 문서·절에 강제되는지, 무엇으로 확인하는지 쓴다. 확인할 수 없는 요건은 쓰지 않는다. 영역은 인증·권한, 시크릿, 암호화, 입력 검증, 외부 호출, 로그·감사, 의존성·빌드, 격리, 비용·남용.

작성 예:

| 번호 | 요건 | 위협 | 강제되는 곳 | 확인 방법 |
|---|---|---|---|---|
| S-01 | 모든 주문 API는 요청자의 역할과 주문 소유를 서버에서 검사한다 | T-01, T-02 | 아키텍처 §5 인증·권한, API 계약 orders 각 엔드포인트 | 다른 사용자 주문 조회 테스트 TC-41, 담당자 계정으로 관리자 API 호출 TC-42 |
| S-02 | 시크릿은 환경변수가 아니라 권한 0600 파일의 경로로만 전달하고, 로그·에러 응답·저장소에 값이 나타나지 않는다 | T-04 | 아키텍처 §5 시크릿, 코드 규칙 로깅 절 | 로그·응답 전체에서 키 형식 문자열 검색 0건, 저장소 검색 0건 |
| S-03 | 서버가 호출하는 외부 주소는 허용 목록(결제 대행사 도메인)뿐이고 사용자 입력은 주소가 되지 않는다 | T-03 | 흐름 설계 결제, worker 코드 | 내부 주소를 콜백으로 넣는 테스트 TC-43 |
| S-04 | 인증 실패와 권한 거부는 사용자·시각·대상과 함께 로그에 남기고 90일 보관한다 | T-01 | 아키텍처 §5 로그, 모니터링 문서 | 로그 샘플 확인 |

## 4. 결정이 필요한 것

이 요건 때문에 아키텍트가 정해야 하는 레벨 1 결정을 적는다. 여기서 정하지 않는다.

작성 예:

| 요건 | 정할 것 | 후보 |
|---|---|---|
| S-02 | 시크릿 보관·전달 방식 | 파일 경로 / 비밀 관리자 |
| S-01 | 권한 검사 계층 | 미들웨어 / 각 핸들러 |

## 5. 검증 계획

요건 번호와 테스트·검토 방법의 대응. 테스트 계획과 보안 검토 task가 이 표를 입력으로 쓴다.

작성 예:

| 요건 | 방법 | 언제 |
|---|---|---|
| S-01 | TC-41, TC-42 자동 테스트 | 백엔드 task 리뷰 |
| S-02 | 로그·저장소 검색 | 보안 검토, run 종료 |
| S-03 | TC-43 | worker task 리뷰 |
