이 문서는 장애가 났을 때 무엇을 하는지 정한다. 증상마다 확인하는 방법, 조치, 조치가 됐는지 확인하는 방법을 명령 단위로 적는다. 모니터링의 알람마다 대응하는 절이 있어야 한다. 새벽에 처음 보는 사람도 따라 할 수 있게 쓴다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 증상: API 5xx 비율 상승

증상마다 절 하나. 확인, 조치, 확인 순서로 쓴다.

작성 예:

- 확인: `tail -n 200 /var/log/orders/api.log | grep '"level":"ERROR"'`로 오류 종류를 본다. DB 연결 오류면 2로, 그 밖이면 3으로.
- 조치 2: `docker compose ps postgres`로 DB 상태 확인. 내려가 있으면 `docker compose up -d postgres`.
- 조치 3: 최근 배포가 10분 안이면 되돌린다(배포 문서 §5). 아니면 `docker compose restart api`.
- 확인: 5분 동안 5xx 비율이 0.1% 아래로 내려오는지 대시보드에서 본다.

## 2. 증상: 결제 대기 10분 초과 주문

작성 예:

- 확인: `docker compose logs --since 15m worker | tail -n 100`. worker가 멈춰 있으면 로그가 없다.
- 조치: `docker compose restart worker`. 재시작 뒤에도 처리되지 않으면 결제 대행사 상태 페이지를 확인한다.
- 확인: `SELECT count(*) FROM orders WHERE status='payment_pending' AND updated_at < now() - interval '10 min'`이 0이 되는지 본다.

## 4. 도움 요청

혼자 해결할 수 없을 때 누구에게 어떻게 연락하는지 적는다.

작성 예:

| 조건 | 누구 | 방법 |
|---|---|---|

| 결제 대행사 장애 | 대행사 기술 지원 | 계약서의 긴급 연락처 |
