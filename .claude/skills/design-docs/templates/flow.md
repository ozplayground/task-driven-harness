# 흐름 이름 설계

| 항목 | 내용 |
|---|---|
| 관련 요구사항 | |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 여러 모듈을 거치는 흐름 하나가 정확히 어떻게 도는지 정한다. 누가 시작하고, 어떤 순서로 무엇이 일어나고, 중간에 실패하면 어떻게 되는지를 단계 번호로 쓴다. 구현하는 사람이 순서나 실패 처리를 스스로 정해야 하는 곳이 없어야 한다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 시작 조건

이 흐름을 무엇이 시작하는지 적는다. 사용자 동작, API 호출, 시간, 다른 흐름의 결과.

작성 예:

> 담당자가 결제 실패 주문에서 재시도를 요청한다(POST /orders/{id}/payment-retry).

## 2. 참여 모듈

이 흐름에 관여하는 모듈과 각각의 역할을 적는다.

작성 예:

| 모듈 | 역할 |
|---|---|
| api | 요청을 받아 주문 상태를 바꾸고 작업을 등록한다 |
| worker | 작업을 받아 결제 대행사에 재시도를 요청하고 결과를 기록한다 |
| 결제 대행사 | 결제를 처리하고 결과를 돌려준다 |

## 3. 순서

단계마다 번호, 누가, 무엇을, 그 결과를 적는다. 한 트랜잭션에 묶이는 단계는 표시한다.

작성 예:

| 단계 | 주체 | 동작 | 결과 |
|---|---|---|---|
| 1 | api | 주문 상태가 payment_failed인지 확인한다 | 아니면 409 PAYMENT_ALREADY_PENDING |
| 2 | api | 상태를 payment_pending으로 바꾸고 재시도 작업을 등록한다 (한 트랜잭션) | 202 응답 |
| 3 | worker | 작업을 받아 결제 대행사에 재시도를 요청한다 | 결과 수신 |
| 4 | worker | 결제 시도 기록을 남기고 주문 상태를 paid 또는 payment_failed로 바꾼다 | |

## 4. 실패와 재시도

단계마다 실패할 수 있는 경우와 그때 어떻게 하는지 적는다. 같은 요청이 두 번 와도 결과가 하나가 되도록 어떤 키로 막는지도 적는다.

작성 예:

| 단계 | 실패 | 처리 | 중복 방지 |
|---|---|---|---|
| 2 | DB 오류 | 트랜잭션 롤백, 500 | Idempotency-Key로 같은 요청은 처음 응답을 돌려준다 |
| 3 | 결제 대행사 응답 없음 (30초) | 1분 간격으로 3회 재시도. 그래도 실패하면 payment_failed | 대행사 요청에 주문 id + 시도 번호를 키로 보낸다 |
| 4 | DB 오류 | 작업을 실패로 두고 5분 뒤 다시 | 상태 갱신은 시도 번호를 조건으로 건다 |

## 5. 상태

이 흐름이 바꾸는 상태와 전이를 적는다.

작성 예:

| 현재 상태 | 사건 | 다음 상태 |
|---|---|---|
| payment_failed | 재시도 요청 | payment_pending |
| payment_pending | 결제 성공 | paid |
| payment_pending | 결제 실패 (재시도 소진) | payment_failed |

## 6. 경계 조건

동시에 여러 요청이 올 때, 한도를 넘을 때, 시간이 오래 걸릴 때 어떻게 하는지 적는다.

작성 예:

> 같은 주문에 재시도 요청이 동시에 두 번 오면 1단계에서 행을 잠근 뒤 상태를 확인하므로 하나만 통과한다. 재시도는 주문당 하루 5회까지다(BR-04).

## 7. 관측

이 흐름이 잘 도는지 어디서 어떻게 확인하는지 적는다. 로그, 지표, 확인 쿼리.

작성 예:

| 무엇 | 어디서 | 알 수 있는 것 |
|---|---|---|
| `payment_retry.requested` 로그 | api | 재시도 요청 건수 |
| payment_pending 상태 10분 초과 주문 수 | 대시보드 쿼리 | worker가 멈췄는지 |

## 8. 대조 표

이 문서가 따르는 결정 기록과 받아내는 요구를 적는다.

작성 예:

| 따르는 결정 | 받아내는 요구 |
|---|---|
| ADR-002 큐 | REQ-02 FN-02, BR-03, BR-04 |
