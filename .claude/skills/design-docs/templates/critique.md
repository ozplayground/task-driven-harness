# 대상 비판 round 1

| 항목 | 내용 |
|---|---|
| 작성자 | critic |
| run | |
| 대상 | 문서 경로 (문서 비평) 또는 원장 (계획 비판) |
| 라운드 | 1 |
| 결론 | 무이의 / 이의 있음 (번호) |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 critic이 문서의 내용을 비평하거나, 구현 투입 전 계획을 비판한 기록이다. 산출물이 기준을 채웠는지 보는 리뷰와 다르다. 여기서는 내용 자체를 따진다. 요구에 비해 과한 설계는 아닌지, 필요 없는 기술을 쓴 건 아닌지, 기술 스택과 수치를 왜 그렇게 정했는지 근거가 있는지, 정했어야 할 것이 빠지진 않았는지, 다른 문서와 어긋나진 않는지. 고치지 않고 항목만 낸다. 항목마다 리더가 따라가 확인할 수 있는 방법을 적는다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 읽은 것

비평한 문서와 함께 읽은 입력 문서의 경로를 적는다.

작성 예:

> 대상: `docs/design/architecture.md` (2026-09-20 판)
> 함께 읽은 것: `docs/prd/orders.md`, `docs/research/queue-options.md`, `docs/decisions/001~008`

## 2. 항목

읽으면서 걸린 것을 하나씩 적는다. 번호(P-Cn), 종류, 심각도, 대상(문서의 절이나 task), 내용, 확인 방법. 종류는 문서 비평이면 과잉 설계, 불필요한 기술, 근거 부족, 누락, 모순, 요구 대비 중 하나, 계획 비판이면 완료 기준, 선행 누락, 경계, 범위, 조사 결손 중 하나. 심각도는 blocker(이대로 가면 요구를 못 채우거나, 근거 없이 되돌리기 어려운 결정이 내려지거나, 뒤 작업이 짐작해야 함), major(재작업이나 재계획 가능성이 높거나, 필요 없는 기술·계층이 유지 부담을 만듦), minor.

작성 예 (아키텍처 문서 비평):

| 번호 | 종류 | 심각도 | 대상 | 내용 | 확인 방법 |
|---|---|---|---|---|---|
| P-C1 | 근거 부족 | blocker | §4 스택 표 | PostgreSQL 16으로 적혀 있는데 왜 16인지 없다. 18이 최신 메이저이고 ADR-003도 버전을 말하지 않는다 | §4 표, ADR-003 §4 |
| P-C2 | 불필요한 기술 | major | §3, §4 | 세션 저장용으로 Redis를 넣었는데 요구에 세션 공유가 없다. 사용자 30명이면 PostgreSQL 테이블로 충분하다 | PRD §6 NFR-01, §4 표 |
| P-C3 | 과잉 설계 | major | §3 | 결제 결과 처리를 별도 서비스로 뗐다. 처리량 초당 10건에 작업자 프로세스 하나면 된다. 서비스 분리의 이유가 없다 | PRD NFR-03, ADR-001 §2 |
| P-C4 | 누락 | blocker | §5 공통 규약 | 에러 응답 형식이 없다. api와 web이 각자 정하게 된다 | §5 표 |
| P-C5 | 모순 | major | §5, 데이터 모델 §2 | 아키텍처는 시각을 UTC로 저장한다고 하는데 데이터 모델의 `failed_at` 설명은 KST다 | 두 문서 해당 줄 |
| P-C6 | 요구 대비 | minor | §3 | 요구에 없는 관리자 대시보드가 실행 단위에 들어 있다 | PRD §4 범위 |

작성 예 (계획 비판):

| 번호 | 종류 | 심각도 | 대상 | 내용 | 확인 방법 |
|---|---|---|---|---|---|
| P-C1 | 완료 기준 | blocker | I1 | NFR-04(목록 1초)가 어느 task 기준에도 없다 | PRD §6 ↔ 원장 I1·I2 기준 |
| P-C2 | 선행 누락 | major | I3 | 화면 task가 API 계약 없이 I1과 동시에 투입된다 | 원장 의존 관계 |

## 3. 이대로 가면

두세 문장으로 무엇이 만들어지고 무엇이 문제로 남을지 적는다.

작성 예:

> 주문 조회와 결제 실패 처리는 만들어진다. 다만 쓸 일 없는 Redis를 운영하게 되고, 에러 형식은 모듈마다 다르게 나온다. DB 버전은 근거 없이 16으로 굳는다.

## 4. 이전 라운드 항목 (round 2부터)

이전 항목마다 해소됐는지 적는다. round 2에는 새 항목을 고치다 생긴 것과 blocker만 올린다.

작성 예:

| 번호 | 상태 | 확인 |
|---|---|---|
| P-C1 | resolved | 스택 표에 PostgreSQL 18, 이유, ADR-003 링크 |
| P-C2 | resolved | Redis 제거, 세션은 PostgreSQL 테이블 |
| P-C3 | open | 서비스 분리 이유가 여전히 없음 |
