# run 보고서 — run 이름

| 항목 | 내용 |
|---|---|
| 요청 | 사용자가 한 요청 한 줄 |
| 진행 방식 | 유인 / 무인 (위임장 버전) |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 이 run이 무엇을 왜 만들었고, 무엇을 만들지 못했으며, 사용자가 확인해야 할 것이 무엇인지 남긴다. 다음 run과 다른 사람이 읽는다. 잘된 것보다 문제가 있는 것을 자세히 쓴다. 무인 모드로 돌렸다면 사용자 답이 필요한 질문과 자동으로 내린 결정을 맨 앞에 둔다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 사용자가 답할 질문

무인 모드에서 위임장 범위 밖이라 진행하지 못한 것을 적는다. 범위 안의 결정은 여기 오지 않는다. 그건 2절 자동 결정이다. 질문마다 어떤 가정을 했고, 가정이 틀리면 무엇이 무효가 되는지, 이 결정에 막혀 진행하지 못한 task가 있는지 적는다. 유인 모드였으면 "없음"이라고 쓴다.

작성 예:

| 번호 | 질문 | 취한 가정 | 가정이 틀리면 무효가 되는 것 | 막힌 task |
|---|---|---|---|---|
| Q1 | 주문 보관 기간은 1년이 맞는가 | 1년 | 삭제 배치(I2), 데이터 모델 §5 | 없음 |
| Q2 | 환불도 이 화면에서 처리하나 | 이번 범위 밖 | 없음 | 없음 |

## 2. 자동으로 내린 결정

무인 모드에서 위임장에 따라 사용자 확인 없이 확정한 결정을 적는다. 결정마다 근거 조항, 추천한 쪽, 검증한 쪽. 유인 모드였으면 "없음"이라고 쓴다.

작성 예:

| 결정 | 위임장 조항 | 추천 | 검증 |
|---|---|---|---|
| ADR-002 작업 큐로 procrastinate | §3 | architect | critic r1 무이의, reviewer 비평 confirmed |

## 3. 요구와 결과

받은 것, 요구한 것, 각 요구가 어떻게 됐는지 적는다. 결과마다 근거가 되는 보고서나 실행 보고의 경로를 단다.

작성 예:

> 받은 것: 운영팀장의 요구 메모, 결제 대행사 API 문서.
> 요구: W1 주문 조회, W2 결제 실패 처리, W3 사용자·권한 관리.

| 요구 | 결과 | 근거 |
|---|---|---|
| W1 주문 조회 | 됨. 이름·기간·상태 검색, 1만 건 조회 0.4초 | test-run §3 TC-01~08 |
| W2 결제 실패 처리 | 됨. 재시도 요청과 결과 갱신 | test-run §3 TC-09~15 |
| W3 사용자·권한 | 됨 | reports/I1.md |

## 4. 결정 경위

이 run에서 내린 결정 기록 목록, critic이 이의를 냈지만 받아들이지 않은 항목과 그 이유, 주요 호출 순서를 적는다.

작성 예:

> 결정 기록: ADR-001~008.
> 받아들이지 않은 비판: P-C3 "Redis 큐 대안 미검토" — 조사 문서 §4에서 검토했고 운영 부담 기준으로 기각. critic r2에서 닫힘.
> 순서: 조사 3건 → architect 결정 초안 → reviewer 비평 2회 → critic 2회 → PRD·FSD → 데이터 모델·계약 → 구현 3건 → 통합 검증.

## 5. 문제가 있는 것

알려진 결함, 제약, 가정으로 진행한 것, 알고 넘긴 리뷰 지적, 검증하지 못한 것을 적는다. 이 절이 이 문서의 핵심이다.

### 5.1 알려진 결함과 제약

작성 예:

| 내용 | 영향 | 근거 |
|---|---|---|
| 주문자 이름 검색이 1만 건에서 p95 1.4초로 NFR-04(1초)를 넘는다 | 목록 화면이 느리다 | test-run §4 TC-41 |
| 결제 대행사 실제 연동은 가짜 서버로만 확인했다 | 실제 응답 형식이 다르면 worker가 실패한다 | test-plan §1 |

### 5.2 가정으로 진행한 것

| 가정 | 어디에 표시 | 되돌리는 방법 |
|---|---|---|
| 페이지 크기 20 | FSD REQ-01 §6 [가정] | 상수 하나 |

### 5.3 알고 넘긴 리뷰 지적

| 지적 | 내용 | 넘긴 이유 |
|---|---|---|
| I1-F7 | 로그 문구 오타 | minor, 동작 영향 없음 |

### 5.4 검증하지 못한 것

| 항목 | 이유 | 검증하려면 |
|---|---|---|
| TC-40 처리량 | 로컬 PC에서 부하를 만들지 못했다 | 별도 부하 머신 |

## 6. 다음에 할 것

이번 범위 밖이지만 발견한 것, 후속 과제, 사용자가 결정해야 다음으로 갈 수 있는 것을 적는다.

작성 예:

| 항목 | 출처 |
|---|---|
| 이름 검색 인덱스 개선 (5.1) | test-run §4 |
| 환불 처리 화면 | Q2 |
| `web/lib/date.ts`에 시간대 처리 오류로 보이는 곳 | reports/I3.md 요청 밖 발견 |
