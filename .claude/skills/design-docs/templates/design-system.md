# 디자인 시스템

| 항목 | 내용 |
|---|---|
| 대상 | 제품 이름 |
| 구현 위치 | 예: `web/components/`, `web/styles/tokens.css` |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 화면을 만들 때 쓰는 시각 규칙과 공통 컴포넌트를 정한다. 프론트엔드 task는 여기 정한 토큰과 컴포넌트만 쓰고, 여기 없는 것이 필요하면 이 문서를 먼저 고친다. 화면의 구성과 흐름은 UX 설계 문서가, 각 화면의 요소와 동작은 FSD가 정한다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 방향

이 제품의 화면이 어떤 인상을 줘야 하는지 두세 문장으로 정한다. 사용자와 사용 상황(UX 설계 1절)에서 나와야 한다.

작성 예:

> 운영팀이 하루 종일 켜 두고 빠르게 처리하는 화면이다. 장식 없이 밀도 높게, 상태(결제 실패·대기·완료)가 한눈에 구분되게. 배경은 밝은 중립색, 강조는 상태 색 하나로.

## 2. 색

토큰 이름, 값, 용도를 적는다. 상태 색은 UX 설계의 상태 표현과 맞춘다. 대비 기준을 적는다.

작성 예:

| 토큰 | 값 | 용도 |
|---|---|---|
| `color-bg` | #FAFAF9 | 화면 배경 |
| `color-surface` | #FFFFFF | 카드, 표 |
| `color-text` | #1C1917 | 본문 |
| `color-text-muted` | #78716C | 보조 문구 |
| `color-primary` | #1D4ED8 | 주 동작 버튼, 링크 |
| `color-danger` | #B91C1C | 결제 실패, 되돌릴 수 없는 동작 |
| `color-warning` | #B45309 | 결제 대기 |
| `color-success` | #15803D | 결제 완료 |

> 본문 텍스트와 배경의 대비는 4.5:1 이상.

## 3. 타이포그래피

글꼴, 크기 단계, 굵기, 줄 간격을 적는다.

작성 예:

| 단계 | 크기 / 줄 간격 | 굵기 | 용도 |
|---|---|---|---|
| 제목 | 20px / 28px | 600 | 화면 제목 |
| 소제목 | 16px / 24px | 600 | 절 제목, 표 머리 |
| 본문 | 14px / 20px | 400 | 표 내용, 폼 |
| 보조 | 12px / 16px | 400 | 도움말, 시각 |

> 글꼴: Pretendard, 없으면 시스템 sans-serif. 숫자는 tabular 자릿수.

## 4. 간격과 그리드

간격 단위, 화면 여백, 컴포넌트 안팎 간격, 최대 폭을 적는다.

작성 예:

> 간격 단위 4px. 화면 좌우 여백 24px, 절 사이 24px, 폼 항목 사이 16px, 버튼 안 여백 8px 16px. 본문 최대 폭 1280px, 그 이상은 가운데 정렬.

## 5. 컴포넌트

공통 컴포넌트마다 종류, 상태(기본·호버·눌림·비활성·오류), 크기, 쓰는 자리를 적는다. 여기 없는 컴포넌트는 만들지 않는다.

작성 예:

| 컴포넌트 | 변형 | 상태 | 규칙 |
|---|---|---|---|
| 버튼 | 주(primary), 부(secondary), 위험(danger) | 기본, 호버, 눌림, 비활성, 로딩 | 화면당 주 버튼 하나. 위험 버튼은 확인 대화상자를 거친다 |
| 입력 | 텍스트, 숫자, 날짜, 선택 | 기본, 포커스, 오류, 비활성 | 라벨은 위, 오류 문구는 아래 12px |
| 표 | 기본, 선택 가능 | 로딩(스켈레톤), 빈 상태 | 머리 고정, 행 높이 40px, 숫자는 오른쪽 정렬 |
| 상태 배지 | 실패, 대기, 완료 | — | 2절 상태 색. 텍스트와 색을 함께 써서 색만으로 구분하지 않는다 |
| 대화상자 | 확인, 폼 | — | 폭 480px. 취소 왼쪽, 확인 오른쪽 |
| 알림 | 성공, 오류 | — | 오른쪽 아래, 3초. 오류는 닫을 때까지 |

## 6. 반응형

지원하는 화면 폭 범위와 폭에 따라 달라지는 것을 적는다.

작성 예:

| 폭 | 동작 |
|---|---|
| 1280px 이상 | 기준 배치 |
| 1024~1279px | 상세 화면의 오른쪽 열이 아래로 내려간다. 표는 가로 스크롤 |
| 1024px 미만 | 범위 밖. 지원하지 않는다는 안내 |

## 7. 문구 톤

버튼·안내·오류 문구의 어조와 형식을 정한다. FSD의 문구 원문은 이 규칙을 따른다.

작성 예:

> 존댓말, 짧은 문장. 버튼은 동사로 끝낸다("재시도 요청", "저장"). 오류는 무엇이 잘못됐는지와 무엇을 하면 되는지를 한 문장씩("조회 기간은 90일까지입니다. 기간을 줄여 주세요.").

## 8. 대조 표

이 문서가 따르는 UX 설계의 항목과 결정 기록을 적는다.

작성 예:

| UX 설계 | 이 문서 |
|---|---|
| §6 레이아웃 골격 | §4 그리드, §5 표·대화상자 |
| §8 상태 표현 | §2 상태 색, §5 배지·알림 |
