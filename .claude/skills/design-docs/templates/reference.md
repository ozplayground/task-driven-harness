# 주제 사용 가이드

| 항목 | 내용 |
|---|---|
| 대상 독자 | 이 시스템을 밖에서 쓰는 사람 |
| 참고 문서 | 이 문서가 근거로 삼은 문서. 링크로 적는다. `[요구사항 정의서](../prd/orders.md)` |

이 문서는 외부 독자가 이 시스템을 어떻게 쓰는지 안내한다. 내용은 계약 문서(API)에서 나온다. 계약과 이 문서가 다르면 계약이 맞고 이 문서를 고친다. 독자가 가장 빨리 성공하는 경로를 먼저 보여 주고, 그 다음 작업별 방법, 마지막에 에러 대처를 둔다.

각 절 아래의 설명은 무엇을 어떻게 쓰는지에 대한 안내다. 문서를 완성할 때 지운다.

## 1. 이 가이드가 다루는 것

누가 무엇을 하려고 이 문서를 읽는지, 무엇은 다루지 않는지 적는다.

작성 예:

> 쇼핑몰 시스템이 주문 서비스 API로 주문을 넘기고 결제 상태를 조회하는 방법을 다룬다. 백오피스 화면 사용법은 다루지 않는다.

## 2. 시작하기

처음 쓰는 사람이 가장 짧게 성공하는 경로를 순서대로 적는다. 인증 준비부터 첫 요청과 그 응답까지.

작성 예:

1. 관리자에게 서비스 API 키를 받는다.
2. 아래 요청을 보낸다.
   ```sh
   curl -H "Authorization: Bearer <API 키>" https://orders.example.com/api/v1/orders?size=1
   ```
3. `{"items": [...], "total": 1, ...}`가 오면 준비가 끝난 것이다.

## 3. 작업별 방법

독자가 하려는 작업마다 절을 하나씩 둔다. 단계와 실제 요청·응답 예시를 적는다.

### 3.1 주문 넘기기

작성 예:

> `POST /api/v1/orders`에 주문 항목과 주문자 정보를 보낸다. 같은 주문을 두 번 보내지 않으려면 `Idempotency-Key` 헤더에 쇼핑몰 쪽 주문번호를 넣는다. 응답의 `id`를 보관해 두면 뒤에서 상태를 조회할 때 쓴다.

## 4. 에러와 대처

독자가 만날 수 있는 에러 코드마다 뜻과 대처를 적는다.

작성 예:

| 코드 | 뜻 | 대처 |
|---|---|---|
| VALIDATION_FAILED | 요청 값이 틀렸다 | 응답의 `details`에 어느 필드가 왜 틀렸는지 있다 |
| ORDER_NOT_FOUND | 그런 주문이 없다 | 주문 id를 확인한다 |
| 401 | 키가 없거나 만료됐다 | 관리자에게 새 키를 받는다 |
