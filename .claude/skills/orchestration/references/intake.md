# 적재(intake) — 받은 것을 읽고 결손을 보고한다

받은 문서에 형식을 요구하지 않는다. 읽고, 무엇인지 판정하고, 뒤 task가 필요로 하는 항목이 있는지 확인하고, 없는 것을 **목록으로** 올린다.

## 절차

1. **읽는다.** 받은 문서 전부. 길면 `investigator`에게 이 파일을 함께 넘겨 적재를 위임하고 아래 4번 형식의 결과만 받는다.
2. **무엇인지 판정한다.** 문서의 제목이 아니라 내용으로. "FSD"라고 불러도 실제로는 화면 목록만 있을 수 있다.

   | 종류 | 담고 있는 것 |
   |---|---|
   | 제품 개요 / 아이디어 | 누가, 왜, 무엇을. 기능은 없거나 대략 |
   | PRD (요구사항 정의서) | 요구사항 목록, 요구사항별 정의·우선순위·인수 조건, 범위, 비기능 요구. 동작 상세는 없음 |
   | 기능 명세서(FSD) | 요구사항을 이루는 기능 목록과 기능별 화면·구성 요소·흐름·규칙·입력 검증·문구·권한·예외 |
   | 교환 규격 / API 스펙 | 엔드포인트, 요청·응답 형태, 에러 코드 |
   | 디자인 산출물 | 화면 구조, 컴포넌트, 토큰 |
   | 기존 코드 | 구조, 스택, 규약, 현재 동작 |

3. **요구가 필요로 하는 항목을 대조한다.** 요구별 필요 항목은 아래 표. 표에 없는 요구는 리더가 같은 방식으로 필요 항목을 정한다.

   | 요구 | 있어야 하는 것 |
   |---|---|
   | 프론트 구현 | 화면 목록과 각 화면의 동작, 입력 검증, 에러 표시, 데이터 출처(API 또는 목), 기술 스택 |
   | 백엔드 구현 | 엔드포인트 또는 유스케이스, 데이터 모델, 검증 규칙, 에러 카탈로그, 권한, 기술 스택 |
   | PRD 작성 | 아이디어 또는 제품 개요, 목표, 대상 |
   | FSD 작성 | PRD(해당 REQ의 정의·인수 조건), 대상 사용자·역할, 범위 경계 |
   | 버그 수정 | 재현 절차 또는 증상, 기대 동작 |
   | 최적화 | 대상, 측정 기준, 허용 변경 범위 |

4. **결손 보고.** 채우지 않는다. 다음 형식으로 사용자에게 올린다.

   ```
   받은 것: docs/order-fsd.md → 기능 명세 (화면 4개, 상태 전이 있음, 에러 카탈로그 없음)
   요구: 주문 화면 + 주문 API

   결손:
   G1 [결정]      기술 스택 — 저장소에 package.json 없음. 무엇으로?
   G2 [계약]      교환 규격 — 화면과 API가 갈라지므로 선행 task로 만든다 (확인 불필요)
   G3 [중간산출물] 에러 메시지 문구 — 명세에 없음. 실행자가 정하게 둘까, 지금 정할까?
   ```

5. **사용자 응답을 notes.md에 적는다.** "알아서 해"라는 답도 기록한다. 그 경우 결손은 실행자의 "명세에 없어 내가 정한 것"으로 내려간다.

## 결손 분류 기준

| 종류 | 판정 | 처리 |
|---|---|---|
| **결정** | 나중에 바꾸면 만든 것을 다시 만들어야 하는가 → 예 | 묻는다. 답 없이 진행하지 않는다 |
| **중간 산출물** | 요구하지 않았고, 없어도 요구를 만들 수 있는가 → 예 | 필요하면 계획에서 선행 task로 둔다. 사용자에게 보이고 뺄 수 있게 |
| **계약** | 둘 이상의 task가 같은 것을 참조하는가 → 예 | 선행 task로 만든다. 묻지 않는다 |

결정의 예: 언어·프레임워크, 데이터베이스, 저장소 구조, 인증 방식, 배포 대상, 공개 API의 형태.
중간 산출물의 예: 와이어프레임, 디자인 시스템. (조사·테스트 계획·설계 문서는 중간 산출물이 아니라 계획의 선행 task다.)
계약의 예: 교환 규격, 공유 타입, 데이터베이스 스키마, 공통 유틸리티, 에러 코드 표.

## 흔한 실패

| 증상 | 원인 |
|---|---|
| 실행자가 각자 다른 응답 형태를 만듦 | 계약을 선행 task로 빼지 않고 양쪽에 "알아서"로 넘김 |
| 사용자가 "그거 내가 준 문서에 있는데"라고 함 | 문서를 제목으로 판정하고 내용을 읽지 않음 |
| 진행 중 스택이 바뀜 | 결정을 중간 산출물로 잘못 분류해 기본값으로 진행 |
| 질문이 열 개 넘게 나감 | 되돌릴 수 있는 세부까지 결정으로 분류 |
